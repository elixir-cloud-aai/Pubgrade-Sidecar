Pubgrade-Sidecar 0.3.1 says why it couldn't find the image of a
notification: each failed check of the registry is logged with its reason
(e.g., Docker Hub's 429 when the cluster's shared egress IP has used up the
anonymous rate limit), and a failed delivery reports it in `detail`. It
honours `Retry-After`, and the chart value `imageWait` sets how long a
notification waits for its image. A weekly canary now checks that upgrades
reach the live deployments. The API stays at version 4.1.0. Until 1.0.0,
releases are pre-releases. Read the [upgrade
notes](https://github.com/elixir-cloud-aai/Pubgrade-Sidecar/blob/v0.3.1/docs/deployment.md#upgrading-to-chart-version-031)
before upgrading (don't use `helm upgrade --reuse-values`), and see
[Registries](https://github.com/elixir-cloud-aai/Pubgrade-Sidecar/blob/v0.3.1/docs/deployment.md#registries)
for Docker Hub credentials.

## Features

- The chart value `imageWait` (`retries`, default 3, and `interval` in
  seconds, default 30, the wait that was fixed before; environment variables
  `IMAGE_WAIT_RETRIES` and `IMAGE_WAIT_INTERVAL`) sets how long a
  notification waits for its image. After a 429 or 503 with `Retry-After`
  from the registry or its token service, the next check waits that long, if
  it fits in the rest of the wait, and a delivery that a newer notification
  replaces stops within 5 seconds (#85, #84)

## Fixes

- A failed image check was reported only as "Image of a notification isn't
  available", without the reason. Each failed check is now logged at the
  level WARNING with the status code of the registry or its token service
  and its rate-limit headers, or the class of the network error, never
  tokens, credentials or URLs; `GET /deployment/{name}` reports the reason
  of the last check in `detail`. The deployment docs explain the reasons in
  a troubleshooting table, and how to avoid Docker Hub's anonymous rate limit
  with `registryCredentials` (#85, #84)

## Maintenance

- The workflow `Canary` releases a tiny image once a week (and by hand),
  notifies Pubgrade and checks that every site in `CANARY_SITES` rolled it
  out through its sidecar within 10 minutes; CI builds the canary image and
  smoke-tests it (#86, #87)

Pubgrade-Sidecar 0.3.0, released together with
[Pubgrade](https://github.com/elixir-cloud-aai/Pubgrade) 0.3.0, removes an
unused call from the API (API 4.0.0) and adds two optional settings that let
it roll out only upgrades, and only tags that match a pattern (API 4.1.0). It
makes the security contexts of its Helm chart configurable, so that it
deploys on clusters that reject pods naming a seccomp profile (e.g., CSC
Rahti since November 2026), and keeps its CPU limit and request within the
ratio that LimitRanges often enforce. It also adds a script that checks a
deployed sidecar. Until 1.0.0, releases are pre-releases. Read the [upgrade
notes](https://github.com/elixir-cloud-aai/Pubgrade-Sidecar/blob/v0.3.0/docs/deployment.md#upgrading-to-version-400-of-the-api)
and the chart's [security
contexts](https://github.com/elixir-cloud-aai/Pubgrade-Sidecar/blob/v0.3.0/docs/deployment.md#security-contexts)
and [resources](https://github.com/elixir-cloud-aai/Pubgrade-Sidecar/blob/v0.3.0/docs/deployment.md#resources)
before upgrading, and see [Refusing
downgrades](https://github.com/elixir-cloud-aai/Pubgrade-Sidecar/blob/v0.3.0/docs/deployment.md#refusing-downgrades)
for the new settings.

## Breaking changes

- API 4.0.0: remove `DELETE /deployment/{deployment-name}`, which deleted the
  pod of that name (not a deployment), which Pubgrade never called and which
  the chart's Role refused; it now gets a 405 (#58, #59)

## Features

- `tests/check_deployment.sh` checks a deployed sidecar over its public URL,
  read-only: HTTPS only, the access token, and the target and non-target
  deployments (#63, #64)

## Security

- The optional chart values `refuseDowngrades` and `allowedTags`
  (environment variables `REFUSE_DOWNGRADES` and `ALLOWED_TAGS`) let the
  sidecar roll out only upgrades (a higher version than the current tag of
  every container it would change), and only tags that match a pattern. It
  refuses other notifications with a 409 and changes nothing; a deployment
  that changes while its delivery waits for the image fails only its own
  delivery, and the others still roll out. Both are off by default (API
  4.1.0) (#78, #79)

## Fixes

- The chart's security contexts are the values `podSecurityContext` and
  `securityContext`, with the earlier settings as defaults;
  `podSecurityContext.seccompProfile=null` removes the seccomp profile, e.g.,
  for CSC Rahti. Don't upgrade from chart 0.2.0 with `--reuse-values` (#61,
  #62)
- The chart sets a CPU limit of 250m to its 50m request, so that the default
  limit of a LimitRange no longer applies and the ratio stays at 5 (#65, #66)
